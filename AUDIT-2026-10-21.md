## 1. Julius.ai — reverse-engineering notes

### Method and evidence

- REA static analysis of the public Next.js bundle: **37 JavaScript files**, **550 modules**, **2,178,578 bytes** of source, **1,795 findings**.
- Evidence ID: `ev_2ec654bb488055d69e68347cf80403ef1647e3b2486d68ee6de5b09eb833cc61`
- Confidence: `derived`; authority: `shipped-artifact`.
- The live browser path was blocked by Cloudflare (`Just a moment…`), so the analysis is **static**: the page HTML and its chunks were fetched directly and parsed as inert text. Nothing was executed.
- This is the **marketing/unauthenticated surface**, not the logged-in product. API hosts and app-only routes behind auth are not recoverable from these chunks.

- **Core workspace:** `/chat`, `/files`, `/library`, `/settings/subscription`, `/refer`, `/pricing`, `/docs`
- **Artifacts:** Excel AI, website builder, slides/presentations, image generator, video generator, report generator
- **Data connectors:** Snowflake, BigQuery, Postgres, Google Drive (logos in bundle)
- **Use cases:** finance, marketing, product, RevOps, education, data science, scientific research
- **Plans:** `success_basic`, `success_pro`, `success_premium`
- **Launch copy:** “Julius 1.5”, “Browser Agent”, “Custom brand templates”

### What this means for BuildifyLabs

Julius competes on **breadth** (chat → spreadsheet/slides/site/video) and **connectors**. BuildifyLabs' defensible difference is **traceability**: exact SQL, raw row slice, evidence and confidence per answer. Do not chase artifact breadth before the trust loop is flawless.

Table stakes worth copying (in order): passkeys/MFA, real connector onboarding, export/publish of results, and a clear plan/quota UX.

### 2.2 Remaining blockers (P0 — do not launch without these)

1. **Payments are fully mocked.**
   `Frontend/src/api/payments.ts` returns `order_mock_<timestamp>` and an empty payment list. There is no backend order/webhook route, no signature verification, and no `users.plan` upgrade path. The UI can show a Pro plan that cannot actually be bought.
   *Fix:* Razorpay Orders API server-side, checkout signature verification, idempotent webhook, plan update, refund/cancel path, test-mode E2E.

2. **Uploads live on local disk.**
   `Backend/app/services/data/storage.py` writes to `UPLOAD_DIR`. The Dockerfile itself notes this is ephemeral on App Runner/EC2. Files vanish on redeploy and are inconsistent across replicas.
   *Fix:* S3/R2 object storage with signed URLs and lifecycle rules; keep the storage seam.

3. **Production API URL can silently fall back to localhost.**
   `Frontend/src/lib/http.ts` uses `VITE_API_BASE_URL ?? 'http://localhost:8000'`. A missing env var in Vercel produces a deployed app that calls the user's own machine.
   *Fix:* fail the build when `PROD` and the variable is absent, or proxy `/api` same-origin.

4. **Rate limiting is per-process, in memory.**
   `Backend/app/middlewares/auth_rate_limiter.py` documents this. With 2+ uvicorn workers or 2+ instances, every limit is multiplied; login brute-force and guest-account farming become practical.
   *Fix:* Redis sliding window (the `REDIS_URL` setting already exists) for login/guest/contact, and consider a shared chat quota guard.

5. **No dependency/secret scanning and no branch protection.**
   CI now exists, but the repo has no `pip-audit`/`npm audit`, Dependabot, or secret scanning. `Backend/requirements.txt` is entirely unpinned.

### 2.3 High priority (P1)

- **Refresh tokens are not revocable.** A new refresh token is issued on every refresh, but the old one stays valid for its full 7 days. Password reset does not invalidate existing sessions. Add `jti` + `token_version` (or a denylist) and reuse detection.
- **Guest identity is a bearer secret.** `/auth/guest` returns a full session for any `device_id`. Anyone who learns another guest's id gets their history. Bind guests to a signed, http-only cookie or treat guest data as disposable.
- **Upload validation trusts the client.** `file_validator.py` checks extension + declared `content_type`, not magic bytes. Add `filetype`/`python-magic`, stream to disk instead of reading the whole file twice, and scan PDFs/XLSX for active content.
- **Migrations run at container start.** With more than one replica, `alembic upgrade head` races on `alembic_version`. Run it as a separate deploy step.
- **No SQL statement timeout.** `sanitize_sql` requires a `LIMIT` but does not cap its value; `LIMIT 100000000` on a large table can pin the DB. Set `statement_timeout` (e.g. 10 s) on the execution session and cap the limit.
- **Connection pool sizing.** 10 + 20 overflow per worker; four workers can exceed a small Neon plan. Tune `DB_POOL_SIZE`/`DB_MAX_OVERFLOW` by worker count or put PgBouncer in front.
- **No observability.** Add structured JSON logs, request IDs, Sentry (frontend + backend), latency/error metrics, and an alert on `/health`.
- **808 KB JavaScript in one chunk** (234 KB gzip). Recharts is the main weight. Use route-level `React.lazy` and `manualChunks`; the build warning is real.
- **Signup reveals registered emails** (`User already exists`). Consider the generic “check your inbox” pattern if enumeration matters for your threat model.
- **No pagination** on `GET /files` (and likely activity/history). Fine at small scale, a latency problem later.

### 2.4 Low priority / cleanup (P2)

- Pydantic v2 `class Config` deprecations in `schemas/auth.py` and `schemas/file_upload.py`.
- `pd.to_datetime(..., errors="coerce")` emits format-inference warnings; pass an explicit format or silence deliberately.
- `get_table_columns` falls through from `information_schema` to SQLite `PRAGMA`; on Postgres an empty result would produce a confusing error. Branch on dialect explicitly.
- Consider a CSP at the edge (Vercel/nginx). The API's Swagger UI needs nonces, so it is easier there than in FastAPI.
- `Backend/docker-compose.yml` is empty; either provide a local Postgres+pgvector service or remove the file.

## 4. Go-live checklist

**Environment**
- `ENVIRONMENT=production`
- `DATABASE_SSL=true` (or `false` for local Postgres)
- `TRUST_PROXY_HEADERS=true` **only** behind App Runner/Vercel/nginx
- `ALLOWED_ORIGIN=https://your-domain` (exact origin, no trailing slash)
- `JWT_SECRET` ≥ 32 random bytes (current local value is 64 chars)
- `VITE_API_BASE_URL=https://api.your-domain`
- `SMTP_*`, `GOOGLE_CLIENT_ID`, Groq keys, web-search key

**Infrastructure**
- Postgres with `CREATE EXTENSION vector;`
- Redis for shared rate limits
- S3/R2 for uploads
- Separate migration job (`alembic upgrade head`)
- Health checks on `/health`, graceful shutdown, ≥2 replicas
- Sentry + log drain + uptime monitor

**Product**
- Real payments or hide the upgrade UI
- Legal: privacy policy, terms, data retention/deletion, DPA if selling to businesses
- Backup/restore drill and a documented RTO/RPO
